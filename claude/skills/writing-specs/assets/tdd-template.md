# Feature technical design

> This document records the current design and evolves with authorized work. Draft status or missing independent review does not itself block implementation. Baseline descriptions and non-goals are not permanent constraints. Explicit repository approval rules still apply.

## Objective and scope

Link product intent or the current task. Define the affected behavior and current non-goals.

## Current baseline

Summarize relevant existing behavior with code/configuration references.

## Design and decisions

Describe the proposed flow and responsibilities; use a diagram if useful.

- Required invariants: state the reason/source for each applicable constraint.
- Chosen design: explain important decisions and trade-offs.
- Implementation freedom: identify details the coding agent may choose where ambiguity would otherwise restrict it.

## Contracts and data

Describe affected interfaces, ownership, and state changes. Link canonical schemas and unchanged shared designs.

## Failure behavior and risks

Cover only relevant failure/recovery, security, consistency, compatibility, migration, rollout, or operational concerns. Split into focused sections when needed.

Label assumptions and open decisions, stating the impact and dependent work.

## Verification

Describe observable outcomes and focused tests or commands. Distinguish planned checks from executed evidence. Link an execution plan or add milestones only for changes that benefit from them.

## Related documents and history

Link relevant PRDs, ADRs, contracts, and plans. Record meaningful changes; editorial edits need only an updated date.
